# Система проверки контрагентов и первичной документации (ООО «Валдэкс»)

ВКР бакалавра, 09.03.03 «Прикладная информатика». Django 5 + PostgreSQL + Bootstrap 5. Источники данных по умолчанию
работают в режиме `mock` (синтетические фикстуры), поэтому демо не требует интернета.

## Установка и запуск

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env                       # при необходимости поправьте значения
docker compose up -d db                    # PostgreSQL 15 (или свой сервер — см. POSTGRES_* в .env)
python manage.py migrate
python manage.py seed_demo                 # пользователи, 8 демо-контрагентов, история проверок
python manage.py runserver                 # http://127.0.0.1:8000
```

`seed_demo` работает только при `DEBUG=True` (в `config.settings.dev` так и есть) и безопасен для повторного запуска.
Bootstrap и Chart.js лежат в `static/vendor/`, CDN не используется.

## Демо-пользователи (только для разработки!)

| Логин | Пароль | Роль (группа) | Что видит |
|---|---|---|---|
| `buh_demo` | `BuhDemo-2026` | Бухгалтерия | дашборд, быстрая проверка, карточка (кроме вкладки «Риски» с факторами), форма проверки документа |
| `sb_demo` | `SbDemo-2026` | СБ и юристы | всё то же + детальные факторы риска со ссылками на источники |
| `admin_demo` | `AdminDemo-2026` | Администратор | то же, что СБ, + админка `/admin/` |

Эти пароли публично известны: не создавайте такие записи на рабочем сервере. Для админки у пользователя должен быть
флаг `is_staff` (у `admin_demo` он стоит). Группы создаются миграцией `apps/core/0001_roles`; пользователь без группы
получает 403.

## Переменные окружения

См. `.env.example`: `DJANGO_SECRET_KEY`, `POSTGRES_*`, режимы источников `SOURCE_MODE_<ИСТОЧНИК>` (`mock` | `api` | `web`),
`EGRUL_API_KEY` (DaData, для режима `api`), переопределения весов скоринга `RISK_<КЛЮЧ>`. Секреты в репозиторий не кладутся.
