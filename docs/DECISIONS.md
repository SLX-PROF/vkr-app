# Архитектурные решения

## ADR 01 Django и серверные шаблоны
Контекст: формы, вход, роли, карточки и администрирование небольшой внутренней ИС.
Решение: Django 5 с ORM, миграциями, группами пользователей и Bootstrap.
Последствия: единое приложение без отдельного frontend-сервера; API при необходимости выделяется позднее.

## ADR 02 PostgreSQL
Контекст: история проверок, связи документов и неоднородные ответы источников.
Решение: PostgreSQL 15+; связи и ключевые поля реляционные, ответы и факторы — JSONField (jsonb).
Последствия: транзакционное сохранение результата; SQLite не поддерживается, в том числе в тестах.

## ADR 03 Провайдеры источников
Контекст: разные форматы, ошибки и ограничения доступа.
Решение: BaseSource/SourceResult; отдельный класс для каждого источника, режимы mock/api/web.
Последствия: сбой источника не отменяет проверку; отсутствующие сведения явно отмечаются.

## ADR 04 Демонстрационные данные
Контекст: ключи платных API не предоставлены; воспроизводимая защита без внешней сети.
Решение: восемь синтетических контрагентов, mock по умолчанию, маркировка в карточке и PDF.
Последствия: демонстрация не подтверждает сведения реальных компаний. Для ЕГРЮЛ есть api/web,
остальные внешние подключения остаются расширениями по согласованному ТЗ.

## ADR 05 Ограничения внешних сервисов
Контекст: CAPTCHA и условия использования сайтов.
Решение: защиту не обходить; возвращать unavailable, продолжать остальные проверки.
Последствия: частичный результат требует проверки человеком. Запросы ограничены по времени и частоте.

## ADR 06 PDF через ReportLab
Контекст: нужен отчёт без системных HTML-движков и сетевых ресурсов, с русским текстом и таблицами.
Решение: ReportLab Platypus, локальные Noto Sans Regular/Bold под SIL OFL (static/fonts/LICENSE.txt).
Последствия: повторяемая генерация на Windows/macOS/Linux; переносы таблиц и номера страниц.
PDF строится по сохранённому сеансу, учитывает право просмотра факторов; кеширование отключено.
Вместе с результатом сохраняются режимы источников и параметры скоринга.

Источники: https://docs.djangoproject.com/en/5.2/ ; https://www.postgresql.org/docs/16/ ;
https://docs.reportlab.com/reportlab/userguide/ ; https://github.com/notofonts/noto-fonts .

## Уточнение пользователя 08.11.2026: дополнение документами контрагента
Текущий объём сведений по исполнительным производствам признан достаточным. Дополнительные сведения допускается получать от контрагента. Принят комбинированный процесс: автоматические источники → перечень документов/пояснений → проверка ответа сотрудником. Это не означает, что отсутствующий статус производства становится известным, или что слова контрагента автоматически подтверждают ЗСК. Реализовано формирование и скачивание перечня; автоматическая проверка реестра МЧД и полный охват всех УЦ не заявляются закрытыми.
