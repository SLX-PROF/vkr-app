# Постоянный запуск на VPS

Актуальность: 08.11.2026. Используются существующий сервер и бесплатные публичные сервисы.

## Состав

`compose.prod.yml` запускает отдельный PostgreSQL 16, Django через Gunicorn и ежедневное резервирование.
Порт приложения доступен только на сервере: `127.0.0.1:8765`; порт базы не публикуется.
Снаружи подключается Caddy с HTTPS. Изменение других приложений не требуется.

Секреты задаются в `.env` с правами 0600: `POSTGRES_DB`, `POSTGRES_ADMIN_USER`,
`POSTGRES_ADMIN_PASSWORD`, `APP_DB_USER`, `APP_DB_PASSWORD`, `DJANGO_SECRET_KEY`,
`DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`, `BACKUP_UID`, `BACKUP_GID`.
Администратор базы и роль приложения различаются. Роль приложения не имеет прав суперпользователя.
Пароли должны быть случайными; демонстрационные пользователи из README на сервере не создаются.

## Первоначальный запуск

```bash
mkdir -p backups
chmod 700 backups
chmod 600 .env
chmod 644 deploy/init-db.sh deploy/backup-loop.sh
docker compose -f compose.prod.yml build
docker compose -f compose.prod.yml up -d db
docker compose -f compose.prod.yml run --rm web python manage.py migrate --noinput
docker compose -f compose.prod.yml run --rm web python manage.py createsuperuser
docker compose -f compose.prod.yml up -d
```

Статика собирается внутри образа. Для доступа к пользовательским страницам администратору нужно назначить
группу «Администратор». Состояние приложения и БД проверяется через `/health/`.
`check --deploy` оставляет только предупреждения об HSTS для поддоменов и preload: они намеренно
не включены для общего бесплатного DNS-домена.

## HTTPS

Для существующего сервера подготовлен `deploy/enable-https.py`: проверяет DNS,
проверяет новую конфигурацию Caddy до записи, сохраняет исходный файл и при ошибке reload восстанавливает его.
Его выполняет администратор через `sudo python3 deploy/enable-https.py`.
До выполнения и внешней проверки сертификата адрес нельзя считать готовым.

## Резервные копии

Контейнер `backup` делает дамп сразу после запуска, затем раз в 24 часа. Ошибка приводит к повтору через час.
Каждый дамп проверяется командой `pg_restore --list`; права файлов 0600. Автоматического удаления копий нет.
Ручной запуск: `bash deploy/backup-db.sh`. Проверка реального восстановления в отдельную базу выполнена.
Копии находятся на том же VPS: отдельно нужно организовать внешнюю копию и следить за свободным местом.

## Обновления и ограничения

Перед обновлением сделать дамп; затем `docker compose -f compose.prod.yml up -d --build` и `migrate`.
Не удалять том `pgdata`. В рабочей среде не выполнять `seed_demo --force`.

Выполнены реальные запросы с VPS к ЕГРЮЛ, «Прозрачному бизнесу» и реестру дисквалифицированных лиц ФНС.
ФССП, ЕФРСБ и КАД в режиме web пока возвращают «недоступен»: их следует проверять вручную.
При недоступных источниках низкая сумма баллов даёт «Недостаточно данных»; доказанные факторы риска
сохраняют статус «Рискованный» или «Опасный». Публичные веб-сервисы ФНС могут менять формат и требовать CAPTCHA.
